## Fundamentals & global infra (1–10)
1. 🟢🔥 `[GEN]` Region vs Availability Zone vs Edge Location.

    Ans: A Region is a geographical area that contains multiple Availability Zones (AZs). An AZ is a physically separate data center within a Region, designed for high availability and fault tolerance. Edge Locations are part of the AWS Content Delivery Network (CDN) and are used to cache content closer to end-users for lower latency.

2. 🟢🔥 `[TCS]` Shared Responsibility Model — give examples of each side.

    Ans: In the Shared Responsibility Model, AWS is responsible for the security "of" the cloud, which includes the physical infrastructure, network, and virtualization layer. Customers are responsible for security "in" the cloud, which includes configuring security groups, managing IAM users and roles, and securing their applications and data.

3. 🟡 `[WMT]` Multi-AZ vs Multi-Region — HA vs DR, with trade-offs.

    Ans: Multi-AZ deployments provide high availability (HA) within a single Region by replicating resources across multiple Availability Zones. This ensures that if one AZ fails, the application can continue to operate. Multi-Region deployments provide disaster recovery (DR) by replicating resources across different Regions, which can protect against regional outages but may introduce higher latency and increased costs.

4. 🟢 `[INFY]` What are the 6 Well-Architected pillars?

    Ans: The six pillars of the AWS Well-Architected Framework are:
    - Operational Excellence: Focuses on operations in the cloud, including monitoring, incident response,
    and continuous improvement.
    - Security: Protecting data, systems, and assets through risk assessments and mitigation strategies.
    - Reliability: Ensuring a workload performs its intended function correctly and consistently.
    - Performance Efficiency: Using IT and computing resources efficiently to meet system requirements.
    - Cost Optimization: Avoiding unnecessary costs and maximizing the value of cloud investments.

5. 🟡 `[ACN]` What is AWS Organizations and why multi-account?

    Ans: AWS Organizations is a service that allows you to centrally manage and govern multiple AWS accounts. It enables you to create organizational units (OUs), apply policies, and consolidate billing. Multi-account strategies are used for isolation of workloads, security boundaries, and cost management.

6. 🟢 `[CTS]` On-Demand vs Reserved vs Spot vs Savings Plans.

    Ans: On-Demand instances allow you to pay for compute capacity by the hour or second with no long-term commitments. Reserved Instances provide a significant discount (up to 75%) compared to On-Demand pricing in exchange for a one- or three-year commitment. Spot Instances allow you to bid for unused EC2 capacity at potentially lower prices, but they can be terminated by AWS with little notice. Savings Plans offer flexible pricing for EC2 and Fargate usage in exchange for a commitment to a consistent amount of usage (measured in $/hour) for a one- or three-year term.

7. 🟡 `[CAPG]` What is a Service Control Policy (SCP)?

    Ans: A Service Control Policy (SCP) is a type of policy used in AWS Organizations to manage permissions across multiple AWS accounts. SCPs define the maximum available permissions for accounts within an organization or organizational unit (OU). They do not grant permissions themselves but restrict what actions can be performed, ensuring that accounts cannot exceed the defined boundaries.

8. 🟢 `[HEXA]` How does AWS pricing work (pay-as-you-go)?

    Ans: AWS pricing is based on a pay-as-you-go model, where customers are charged only for the resources they use. This includes compute, storage, and data transfer, among other services. Pricing can vary based on factors such as instance type, region, and usage duration. Customers can also take advantage of cost-saving options like Reserved Instances and Savings Plans.

9. 🟡 `[DLT]` What is a landing zone / Control Tower?

    Ans: A landing zone is a well-architected, multi-account AWS environment that provides a secure and scalable foundation for deploying workloads. AWS Control Tower is a service that automates the setup of a landing zone, providing pre-configured best practices for security, compliance, and governance. It helps organizations quickly establish a multi-account structure with centralized management and monitoring.

10. 🟢 `[EY]` What is the Free Tier and its limits?

    Ans: The AWS Free Tier is a program that allows new customers to use certain AWS services for free, up to specified limits, for a limited time (usually 12 months). It includes offers such as 750 hours of EC2 t2.micro or t3.micro instances per month, 5 GB of S3 storage, and 1 million requests per month for Lambda. After the Free Tier period or if usage exceeds the limits, standard pricing applies.

## IAM & security (11–25) 🔥
11. 🟢🔥 `[GEN]` User vs Group vs Role vs Policy.

    Ans: In AWS IAM, a User represents an individual identity with long-term credentials (username and password or access keys). A Group is a collection of users that can be managed together and assigned permissions via policies. A Role is an IAM identity that can be assumed by trusted entities (users, applications, or services) and provides temporary security credentials. A Policy is a JSON document that defines permissions, specifying what actions are allowed or denied on which resources.

12. 🟡🔥 `[AMZN][PP]` What is least privilege? Give a real example.

    Ans: Least privilege is a security principle that recommends granting users, applications, or services only the minimum permissions necessary to perform their tasks. For example, if an application needs to read data from an S3 bucket but does not need to write or delete objects, it should be granted a policy that allows only the "s3:GetObject" action on that specific bucket, rather than full access.

13. 🟡🔥 `[WMT]` How do you give an EC2/ECS app access to S3 without keys?

    Ans: You can give an EC2 or ECS application access to S3 without using long-term access keys by assigning an IAM Role to the EC2 instance or ECS task. The role should have a policy attached that grants the necessary permissions to access the S3 bucket. When the application runs, it can use the temporary credentials provided by the role to interact with S3 securely.

14. 🟡 `[CTS]` Managed vs inline policy.

    Ans: A managed policy is a standalone IAM policy that can be attached to multiple users, groups, or roles. AWS provides AWS-managed policies, and you can also create your own customer-managed policies. An inline policy is embedded directly into a specific user, group, or role and cannot be reused. Inline policies are typically used for permissions that are unique to a single entity.

15. 🔴 `[AMZN]` How does STS AssumeRole work? Cross-account access?

    Ans: AWS Security Token Service (STS) AssumeRole allows an entity (user, application, or service) to assume a role in another account or within the same account. When an entity assumes a role, STS provides temporary security credentials (access key ID, secret access key, and session token) that grant the permissions defined in the role's policy. This enables cross-account access without sharing long-term credentials. The entity must have permission to call the AssumeRole API and the target role must trust the entity's account.

16. 🟡 `[INFY]` Identity-based vs resource-based policy.

    Ans: Identity-based policies are attached to IAM identities (users, groups, or roles) and define what actions those identities can perform on AWS resources. Resource-based policies are attached directly to AWS resources (like S3 buckets or SQS queues) and specify which identities are allowed or denied access to that resource. Resource-based policies can grant cross-account access without needing to create IAM roles in the other account.

17. 🔴🔥 `[PP]` Policy evaluation: what wins — Allow or Deny?

    Ans: In AWS IAM policy evaluation, Deny always takes precedence over Allow. If a user or role has both an Allow and a Deny for the same action on a resource, the Deny will override the Allow, and the action will be denied. This ensures that explicit Deny statements are enforced, even if there are other policies granting permission.

18. 🟡 `[CAPG]` Permission boundary vs SCP.

    Ans: A permission boundary is an advanced feature in AWS IAM that sets the maximum permissions an IAM entity (user or role) can have, effectively limiting the scope of what that entity can do, even if it has policies attached that grant broader permissions. Service Control Policies (SCPs) are used in AWS Organizations to define the maximum available permissions for accounts or organizational units (OUs). SCPs apply to all IAM entities within the account or OU, while permission boundaries are specific to individual IAM entities.

19. 🟡 `[ACN]` What is IAM Access Analyzer?

    Ans: IAM Access Analyzer is a feature in AWS that helps you identify resources in your account that are shared with external entities. It analyzes resource-based policies and generates findings that indicate which resources are accessible from outside your account, allowing you to review and adjust permissions to ensure security and compliance.
    
20. 🟡 `[WMT]` How do you enforce MFA?

    Ans: To enforce Multi-Factor Authentication (MFA) in AWS, you can require users to enable MFA on their IAM accounts. This can be done by creating an IAM policy that denies access to AWS services unless MFA is enabled. Additionally, you can configure AWS Identity and Access Management (IAM) to require MFA for specific actions or resources, ensuring that users must provide a second form of authentication (such as a time-based one-time password from an MFA device) in addition to their regular credentials.

21. 🟡🔥 `[GEN]` Where do you store secrets? Secrets Manager vs Parameter Store vs KMS.

    Ans: Secrets Manager is a service designed for managing sensitive information such as database credentials, API keys, and other secrets. It provides automatic rotation of secrets, fine-grained access control, and auditing capabilities. Parameter Store is a service that allows you to store configuration data and secrets in a hierarchical structure, with support for versioning and encryption using AWS KMS. KMS (Key Management Service) is used to create and manage cryptographic keys for encrypting data, including secrets stored in Secrets Manager or Parameter Store. It provides centralized key management and integrates with other AWS services for secure data encryption.

22. 🟡 `[CMCST]` What does KMS do? Envelope encryption.

    Ans: AWS Key Management Service (KMS) is a managed service that allows you to create and control cryptographic keys used for data encryption. It provides a secure and centralized way to manage encryption keys, including key rotation, access control, and auditing. Envelope encryption is a technique where data is encrypted using a data key, which is itself encrypted with a master key managed by KMS. This approach allows for efficient encryption of large amounts of data while maintaining the security of the master key.

23. 🟡 `[DLT]` GuardDuty vs Config vs Security Hub.

    Ans: GuardDuty is a threat detection service that continuously monitors for malicious or unauthorized behavior in your AWS environment, such as unusual API calls or potentially compromised instances. AWS Config is a service that provides a detailed view of the configuration of your AWS resources, allowing you to assess compliance with best practices and regulatory requirements. Security Hub is a centralized security management service that aggregates findings from various AWS security services (including GuardDuty and Config) and provides a comprehensive view of your security posture, enabling you to prioritize and remediate issues.

24. 🟡 `[PP]` What is a WAF and what does it protect against?

    Ans: AWS Web Application Firewall (WAF) is a security service that helps protect web applications from common web exploits and attacks, such as SQL injection, cross-site scripting (XSS), and distributed denial-of-service (DDoS) attacks. WAF allows you to create custom rules to filter and monitor HTTP and HTTPS requests, providing protection at the application layer. It can be integrated with services like Amazon CloudFront, Application Load Balancer, and API Gateway to enhance the security of your web applications.

25. 🔴 `[AMZN]` How do you give EKS pods IAM permissions? (IRSA)

    Ans: To give EKS pods IAM permissions, you can use IAM Roles for Service Accounts (IRSA). This involves creating an IAM role with the necessary permissions and associating it with a Kubernetes service account. When a pod is launched using that service account, it automatically assumes the IAM role, allowing it to access AWS resources securely without needing to manage long-term credentials. This approach provides fine-grained access control and enhances security by limiting permissions to only what the pod requires.

## VPC & networking (26–42) 🔥
26. 🟢🔥 `[GEN]` What is a VPC? What is CIDR?

    Ans: A Virtual Private Cloud (VPC) is a logically isolated section of the AWS cloud where you can launch AWS resources in a virtual network that you define. It provides control over your network configuration, including IP address ranges, subnets, route tables, and security settings. CIDR (Classless Inter-Domain Routing) is a method for allocating IP addresses and routing IP packets. In the context of a VPC, CIDR notation is used to define the IP address range for the VPC and its subnets (e.g., 10.0.0.0/16).

27. 🟢🔥 `[CTS]` Public vs private subnet — what makes it public?

    Ans: A public subnet is a subnet that has a route to an Internet Gateway (IGW), allowing instances within the subnet to communicate with the internet. This is typically achieved by having a default route (0.0.0.0/0) pointing to the IGW in the subnet's route table. A private subnet, on the other hand, does not have a direct route to the IGW and typically uses a NAT Gateway or NAT instance to access the internet.

28. 🟡🔥 `[WMT][INFY]` Security Group vs NACL (stateful vs stateless, allow vs deny).

    Ans: Security Groups (SGs) are stateful virtual firewalls that control inbound and outbound traffic for EC2 instances. They allow you to specify rules that permit traffic based on IP addresses, protocols, and ports. Because they are stateful, if an incoming request is allowed, the response is automatically allowed, regardless of outbound rules. Network Access Control Lists (NACLs) are stateless firewalls that operate at the subnet level. They allow you to define both allow and deny rules for inbound and outbound traffic. Since they are stateless, return traffic must be explicitly allowed by the NACL rules.

29. 🟡🔥 `[CTS]` Internet Gateway vs NAT Gateway.

    Ans: An Internet Gateway (IGW) is a horizontally scaled, redundant, and highly available VPC component that allows communication between instances in your VPC and the internet. It enables public subnets to have direct access to the internet. A NAT Gateway (Network Address Translation Gateway) is used to enable instances in private subnets to initiate outbound traffic to the internet while preventing inbound traffic from the internet. NAT Gateways allow private instances to access external resources without exposing them directly to the internet.

30. 🟡 `[CAPG]` What is a route table?

    Ans: A route table is a set of rules, called routes, that determine how network traffic is directed within a VPC. Each subnet in a VPC must be associated with a route table, which defines the paths that traffic takes to reach its destination. Routes can direct traffic to various targets, such as an Internet Gateway, NAT Gateway, Virtual Private Gateway, or other subnets within the VPC. Route tables are essential for controlling the flow of traffic and ensuring proper connectivity between resources.

31. 🟡 `[PP]` What is a VPC endpoint? Gateway vs Interface endpoint.

    Ans: A VPC endpoint is a private connection between your VPC and supported AWS services or VPC endpoint services, allowing you to access these services without using an internet gateway, NAT device, VPN connection, or AWS Direct Connect. There are two types of VPC endpoints: Gateway endpoints and Interface endpoints. Gateway endpoints are used for services like Amazon S3 and DynamoDB and are implemented as a target in your route table. Interface endpoints are powered by AWS PrivateLink and provide private connectivity to services over an elastic network interface (ENI) with private IP addresses.

32. 🟡 `[ACN]` VPC Peering vs Transit Gateway.

    Ans: VPC Peering is a networking connection between two VPCs that allows them to communicate as if they are within the same network. It is a one-to-one relationship and does not support transitive routing, meaning that if VPC A is peered with VPC B, and VPC B is peered with VPC C, VPC A cannot communicate with VPC C through VPC B. Transit Gateway, on the other hand, is a scalable and centralized hub that connects multiple VPCs and on-premises networks. It supports transitive routing, allowing for more complex network architectures and easier management of multiple connections.

33. 🟡 `[CMCST]` Elastic IP vs public IP vs private IP.

    Ans: An Elastic IP (EIP) is a static, public IPv4 address that you can allocate to your AWS account and associate with an EC2 instance or other resources. It allows you to maintain a consistent public IP address even if the underlying instance is stopped or terminated. A public IP is an automatically assigned IP address that allows instances to communicate with the internet. It is dynamic and can change when the instance is stopped and started. A private IP is an IP address assigned to an instance within a VPC that is used for internal communication between instances and does not have direct access to the internet.

34. 🔴 `[AMZN]` Design a 3-tier VPC across 2 AZs (draw subnets, routes).

    Ans: A 3-tier VPC architecture typically consists of a web tier, application tier, and database tier. To design this across 2 Availability Zones (AZs), you would create the following subnets:
- Web Tier: Two public subnets (one in each AZ) for the web servers, with a route to the Internet Gateway (IGW) for internet access.
- Application Tier: Two private subnets (one in each AZ) for the application servers, with a route to a NAT Gateway in the public subnets for outbound internet access.
- Database Tier: Two private subnets (one in each AZ) for the database servers, with no direct internet access. The route tables for the application and database tiers would not include a route to the IGW, ensuring that they remain isolated from the internet. Security groups and NACLs would be configured to allow necessary traffic between the tiers while restricting access from external sources.

35. 🟡🔥 `[WMT]` ALB vs NLB vs Gateway Load Balancer.

    Ans: An Application Load Balancer (ALB) operates at the application layer (Layer 7) and is designed to handle HTTP and HTTPS traffic. It provides advanced routing features, such as host-based and path-based routing, and supports WebSocket and HTTP/2 protocols. A Network Load Balancer (NLB) operates at the transport layer (Layer 4) and is designed to handle TCP, UDP, and TLS traffic. It is optimized for high performance, low latency, and can handle millions of requests per second. A Gateway Load Balancer (GLB) is a specialized load balancer that operates at Layer 3 and is used to distribute traffic to virtual appliances, such as firewalls or intrusion detection systems. It allows for seamless integration of third-party network appliances into your VPC architecture.

36. 🟡 `[CTS]` What is a target group and health check?

    Ans: A target group is a logical grouping of targets (such as EC2 instances, IP addresses, or Lambda functions) that a load balancer routes traffic to. Each target group is associated with a specific protocol and port, and it can be used by one or more load balancers. Health checks are used to monitor the health of the targets in a target group. The load balancer periodically sends requests to the targets based on the configured health check settings (protocol, path, interval, timeout, etc.). If a target fails the health check, it is marked as unhealthy and will not receive traffic until it passes the health check again.

37. 🟡 `[INFY]` What is connection draining / deregistration delay?

    Ans: Connection draining, also known as deregistration delay, is a feature of load balancers that allows existing connections to complete before an instance is removed from the target group. When an instance is deregistered or marked as unhealthy, the load balancer stops sending new requests to it but continues to allow existing connections to finish processing. This helps ensure a smooth transition and prevents disruption of service for clients that are already connected to the instance. The deregistration delay can be configured to specify how long the load balancer should wait before terminating the connections.

38. 🟡🔥 `[PP]` What is Route 53? Routing policies (weighted, latency, failover, geolocation).

    Ans: Amazon Route 53 is a scalable and highly available Domain Name System (DNS) web service that translates domain names into IP addresses, allowing users to access websites and applications. It provides various routing policies to control how traffic is directed to different endpoints:
- Weighted Routing: Distributes traffic across multiple resources based on assigned weights, allowing for gradual traffic shifts or A/B testing.
- Latency Routing: Directs traffic to the resource with the lowest latency for the user, improving performance by reducing response times.
- Failover Routing: Automatically routes traffic to a healthy resource if the primary resource becomes unavailable, ensuring high availability.
- Geolocation Routing: Routes traffic based on the geographic location of the user, allowing for content localization and compliance with regional regulations.

39. 🟡🔥 `[WMT]` What is CloudFront? How does edge caching work?
    
    Ans: Amazon CloudFront is a content delivery network (CDN) service that delivers web content, such as HTML, CSS, JavaScript, and media files, to users with low latency and high transfer speeds. It uses a global network of edge locations to cache content closer to end-users. When a user requests content, CloudFront checks if the content is available in the nearest edge location. If it is cached, CloudFront serves it directly from the edge location, reducing the load on the origin server and improving response times. If the content is not cached or has expired, CloudFront retrieves it from the origin server, caches it at the edge location, and serves it to the user.

40. 🟡 `[CMCST]` How do you secure S3 behind CloudFront? (OAC/OAI)

    Ans: To secure S3 behind CloudFront, you can use an Origin Access Control (OAC) or Origin Access Identity (OAI). An OAI is a special CloudFront user that you create to give CloudFront permission to access your S3 bucket. You configure your S3 bucket policy to allow access only from the OAI, effectively preventing direct access to the S3 bucket from the internet. With OAC, you can use signed URLs or signed cookies to restrict access to your content, ensuring that only authorized users can access the resources served through CloudFront.

41. 🔴 `[AMZN]` A private subnet instance can't reach the internet. Debug it.

    Ans: If a private subnet instance cannot reach the internet, you should check the following:
- Ensure that the private subnet has a route to a NAT Gateway or NAT instance in the public subnet. The route table for the private subnet should have a default route (0.0.0.0/0) pointing to the NAT Gateway or NAT instance.

42. 🟡 `[DLT]` What is a bastion host / how do you SSH into private instances? (SSM Session Manager)

    Ans: A bastion host is a special-purpose instance that acts as a secure gateway for accessing instances in private subnets. It is typically placed in a public subnet and allows SSH or RDP access to private instances through it. To SSH into private instances, you can connect to the bastion host first and then use it to access the private instances. Alternatively, you can use AWS Systems Manager Session Manager, which allows you to establish secure shell sessions to your instances without the need for a bastion host or opening inbound ports. Session Manager uses IAM policies for access control and provides logging and auditing capabilities.

## Compute — EC2/ECS/Lambda (43–60) 🔥
43. 🟢🔥 `[GEN]` What is EC2? What is an AMI?

    Ans: Amazon Elastic Compute Cloud (EC2) is a web service that provides resizable compute capacity in the cloud. It allows users to launch virtual servers, known as instances, to run applications and workloads. EC2 offers a variety of instance types, operating systems, and configurations to meet different performance and cost requirements. An Amazon Machine Image (AMI) is a pre-configured template that contains the necessary information to launch an EC2 instance, including the operating system, application server, and any additional software or settings. AMIs can be created by AWS, third-party vendors, or users themselves.

44. 🟢 `[TCS]` Stop vs terminate vs hibernate an instance.
    
    Ans: Stopping an instance means that the instance is shut down, and its resources (CPU, memory) are released, but the instance's data on the EBS volume is preserved. You can start the instance again later, and it will retain its previous state. Terminating an instance means that the instance is permanently deleted, and all associated resources (including EBS volumes) are released. The data on the instance is lost unless you have created snapshots or backups. Hibernating an instance saves the contents of the instance's memory (RAM) to the EBS root volume and stops the instance. When you start the instance again, it resumes from where it left off, restoring the memory state.

45. 🟡 `[CTS]` What is EC2 user data and metadata?

    Ans: EC2 user data is a feature that allows you to provide custom scripts or configuration information to an EC2 instance at launch time. This data can be used to automate the setup and configuration of the instance, such as installing software, configuring services, or running initialization tasks. User data is typically provided in the form of a shell script or cloud-init directives. EC2 metadata is information about the instance itself, such as its instance ID, public and private IP addresses, security groups, and other attributes. Metadata can be accessed from within the instance using a special URL (http://169.254.169.254/latest/meta-data/).

46. 🟡🔥 `[WMT]` What is an Auto Scaling Group? Scaling policies (target/step/scheduled).

    Ans: An Auto Scaling Group (ASG) is a collection of EC2 instances that are managed as a group to provide automatic scaling based on demand. ASGs allow you to maintain the desired number of instances, automatically adding or removing instances based on scaling policies. There are three main types of scaling policies:
- Target Tracking Scaling: Automatically adjusts the number of instances to maintain a specified metric (e.g., CPU utilization) at a target value.
- Step Scaling: Adjusts the number of instances based on a set of predefined thresholds and step adjustments, allowing for more granular control over scaling actions.
- Scheduled Scaling: Allows you to scale the number of instances based on a predefined schedule, such as increasing capacity during peak hours and decreasing it during off-peak hours.

47. 🟡 `[INFY]` Launch template vs launch configuration.

    Ans: A launch template is a resource that contains the configuration information needed to launch EC2 instances, including instance type, AMI ID, key pairs, security groups, and other settings. Launch templates support versioning, allowing you to create multiple versions of the template and easily roll back to a previous version if needed. They also support additional features such as instance metadata options and capacity reservations. A launch configuration is an older resource that serves a similar purpose but does not support versioning or some of the advanced features available in launch templates. Launch configurations are used with Auto Scaling Groups to define the instance settings for scaling operations.

48. 🟡 `[CMCST]` What is a placement group?

    Ans: A placement group is a logical grouping of EC2 instances within a single Availability Zone that allows you to influence the placement of instances to meet specific performance or availability requirements. There are three types of placement groups:
- Cluster Placement Group: Instances are placed close together within a single AZ to provide low-latency network performance and high throughput. This is ideal for applications that require high-performance computing or tightly coupled workloads.
- Spread Placement Group: Instances are placed on distinct underlying hardware to reduce the risk of simultaneous failures. This is suitable for applications that require high availability and fault tolerance.
- Partition Placement Group: Instances are divided into logical partitions, with each partition having its own set of racks. This allows for better fault isolation and is useful for large distributed and replicated workloads.

49. 🟡🔥 `[WMT][PP]` ECS: cluster, task definition, service, task.

    Ans: In Amazon Elastic Container Service (ECS), a cluster is a logical grouping of container instances (EC2 instances or Fargate tasks) that run your containerized applications. A task definition is a blueprint that describes how to run a container, including the Docker image, CPU and memory requirements, networking settings, and environment variables. A service is a long-running task that maintains a specified number of instances of a task definition running in the cluster, ensuring that the desired count is always met. A task is an instantiation of a task definition, representing a single running instance of the containerized application.

50. 🟡🔥 `[CTS]` ECS EC2 launch type vs Fargate.

    Ans: The ECS EC2 launch type allows you to run your containerized applications on a cluster of EC2 instances that you manage. You are responsible for provisioning, scaling, and maintaining the underlying EC2 instances, which gives you more control over the environment but also requires more management overhead. The Fargate launch type is a serverless compute engine that allows you to run containers without managing the underlying infrastructure. With Fargate, you only need to define the task definition and specify the required resources (CPU and memory), and AWS handles the provisioning, scaling, and maintenance of the compute resources. Fargate simplifies container deployment and reduces operational complexity.

51. 🟡 `[HEXA]` What is ECR? How do you push an image?

    Ans: Amazon Elastic Container Registry (ECR) is a fully managed Docker container registry that allows you to store, manage, and deploy Docker container images. To push an image to ECR, you first need to create a repository in ECR. Then, you authenticate your Docker client to the ECR registry using the AWS CLI command `aws ecr get-login-password`. After authentication, you tag your local Docker image with the ECR repository URI and use the `docker push` command to upload the image to the ECR repository.

52. 🟡 `[ACN]` ECS service auto scaling — how?

    Ans: ECS service auto scaling allows you to automatically adjust the number of running tasks in your ECS service based on specified metrics or schedules. To enable auto scaling, you first need to create an Application Auto Scaling policy for your ECS service. You can define target tracking policies, which automatically adjust the desired count of tasks to maintain a specific metric (e.g., CPU utilization) at a target value. Alternatively, you can create step scaling policies that adjust the desired count based on predefined thresholds and step adjustments. You can also set up scheduled scaling to increase or decrease the number of tasks at specific times. Once the policies are configured, ECS will automatically scale the service up or down based on the defined criteria.

53. 🟡 `[PP]` ALB + ECS — how does routing to tasks work?

    Ans: When using an Application Load Balancer (ALB) with ECS, the ALB routes incoming traffic to the appropriate ECS tasks based on the target group associated with the service. Each ECS service is registered with a target group, which contains the IP addresses or instance IDs of the running tasks. The ALB uses its listener rules to determine how to route requests based on factors such as host headers, path patterns, or query parameters. When a request matches a rule, the ALB forwards it to the corresponding target group, which then distributes the traffic to the healthy tasks within that group. Health checks are performed on the tasks to ensure that only healthy instances receive traffic.

54. 🟡🔥 `[CAPG]` What is Lambda? Cold start? Concurrency limits?

    Ans: AWS Lambda is a serverless compute service that allows you to run code without provisioning or managing servers. You can execute code in response to events, such as changes in data, HTTP requests, or messages from other AWS services. A cold start occurs when a Lambda function is invoked for the first time or after it has been idle for a period of time, resulting in additional latency as the execution environment is initialized. Concurrency limits refer to the maximum number of simultaneous executions of a Lambda function. AWS imposes default concurrency limits per account and per function, which can be adjusted by requesting an increase through AWS Support.

55. 🟡 `[CMCST]` Lambda triggers — give 5 event sources.

    Ans: Lambda can be triggered by various event sources, including:
1. Amazon S3: Triggered by events such as object creation or deletion in an S3 bucket.
