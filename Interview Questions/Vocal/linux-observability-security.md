## Linux 🔥
1. 🟢🔥 `[GEN]` Explain `755` vs `644`. How to make a file executable.

    Ans: In Linux, file permissions are represented by a three-digit number. `755` means the owner has read, write, and execute permissions, while the group and others have read and execute permissions. `644` means the owner has read and write permissions, while the group and others have only read permissions. To make a file executable, you can use the `chmod` command, e.g., `chmod +x filename`.

2. 🟡🔥 `[TCS][CTS]` `kill` vs `kill -9`. What is a zombie process?

    Ans: The `kill` command in Linux is used to send signals to processes. `kill` without `-9` sends the default `TERM` signal, which allows the process to gracefully terminate, cleaning up resources. `kill -9` sends the `KILL` signal, which forcefully terminates the process without cleanup. A zombie process is a process that has completed execution but still has an entry in the process table, usually because its parent has not read its exit status.

3. 🟡 `[INFY]` Hard link vs soft link.
    
    Ans: A hard link is a direct reference to the physical data on the disk, meaning multiple filenames can point to the same inode. Deleting one hard link does not affect the others. A soft link (or symbolic link) is a pointer to another file or directory, and it can span across different filesystems. If the original file is deleted, the soft link becomes broken.

4. 🟡🔥 `[WMT]` How do you troubleshoot high CPU / full disk on a server?

    Ans: To troubleshoot high CPU usage, you can use commands like `top`, `htop`, or `ps` to identify processes consuming excessive CPU. For full disk issues, use `df -h` to check disk usage and `du -sh` to identify large directories or files. Additionally, monitoring tools like `iostat`, `vmstat`, and `sar` can provide insights into system performance and resource utilization.

5. 🟢 `[CAPG]` How do you see what's listening on a port?

    Ans: You can use the `netstat -tuln` command to list all listening ports along with their associated processes. Alternatively, `ss -tuln` provides similar information. For more detailed information, you can use `lsof -i :port_number` to see which process is using a specific port.

6. 🟡 `[HEXA]` `systemctl` and `journalctl` — managing a service.

    Ans: `systemctl` is a command-line utility used to manage systemd services, allowing you to start, stop, restart, enable, or disable services. For example, `systemctl start service_name` starts a service, while `systemctl enable service_name` ensures it starts on boot. `journalctl` is used to view logs generated by systemd services. You can use `journalctl -u service_name` to view logs for a specific service or `journalctl -xe` for recent logs with detailed information.

7. 🟢 `[ACN]` `>` vs `>>` vs `2>&1`.

    Ans: In Linux, `>` is used to redirect the standard output (stdout) of a command to a file, overwriting the file if it exists. `>>` is used to append the standard output to a file without overwriting it. `2>&1` is used to redirect the standard error (stderr) to the same location as the standard output, allowing both stdout and stderr to be captured in the same file.

## Observability 🔥
8. 🟢🔥 `[GEN]` Logs vs metrics vs traces.

    Ans: Logs are detailed records of events that happen within a system, providing context and information about specific actions or errors. Metrics are numerical data points that represent the performance or health of a system over time, such as CPU usage or request latency. Traces are records of the execution path of requests through a distributed system, showing how different services interact and where delays may occur.

9. 🟡🔥 `[WMT][PP]` Explain your CloudWatch monitoring + alerting setup. (−50% detection story)

    Ans: In my CloudWatch setup, I configured custom metrics to monitor key performance indicators of our applications. I created dashboards to visualize these metrics and set up alarms to notify the team via SNS when thresholds were breached. This proactive monitoring allowed us to detect issues 50% faster, reducing downtime and improving overall system reliability.

10. 🟡🔥 `[CTS]` CloudWatch vs CloudTrail.

    Ans: CloudWatch is a monitoring and observability service that collects and tracks metrics, logs, and events from AWS resources and applications. It provides real-time insights into system performance and operational health. CloudTrail, on the other hand, is a service that records AWS API calls and events for auditing and compliance purposes. It captures information about who made the request, when it was made, and what actions were taken, helping with security analysis and troubleshooting.

11. 🟡🔥 `[AMZN][WMT]` SLI vs SLO vs SLA. What is an error budget?

    Ans: SLI (Service Level Indicator) is a specific metric that measures the performance or reliability of a service, such as request latency or error rate. SLO (Service Level Objective) is a target value or range for an SLI that defines the acceptable level of service performance. SLA (Service Level Agreement) is a formal contract between a service provider and a customer that outlines the expected level of service and any penalties for not meeting those expectations. An error budget is the allowable threshold of errors or downtime within a given period, calculated based on the SLO, which helps teams balance reliability with innovation.

12. 🟡 `[CMCST]` How do CloudWatch alarms notify? (Alarm→SNS)

    Ans: CloudWatch alarms can notify stakeholders through Amazon Simple Notification Service (SNS). When an alarm state is triggered, it sends a notification to an SNS topic, which can then forward the message to subscribed endpoints such as email addresses, SMS numbers, or HTTP/S endpoints. This allows for real-time alerts and automated responses to system issues.

13. 🟡 `[PP]` Which metrics matter for an API? p50 vs p99 latency.

    Ans: For an API, key metrics include request latency, error rate, and throughput. p50 latency represents the median response time, while p99 latency represents the 99th percentile response time, highlighting the worst-case performance experienced by a small fraction of users. Monitoring both helps ensure a balanced view of typical and extreme performance.

14. 🔴 `[DLT]` How do you avoid alert fatigue?

    Ans: To avoid alert fatigue, it's important to set meaningful thresholds for alerts, prioritize critical issues, and reduce noise by filtering out non-actionable alerts. Implementing alert aggregation, using different notification channels for different severity levels, and regularly reviewing and tuning alert configurations can also help minimize unnecessary notifications.

15. 🟡 `[EY]` MTTR vs MTBF. How did you reduce MTTR?

    Ans: MTTR (Mean Time to Repair) is the average time it takes to restore a system or component after a failure, while MTBF (Mean Time Between Failures) is the average time between failures of a system or component. To reduce MTTR, I implemented automated monitoring and alerting, improved incident response processes, and conducted regular post-incident reviews to identify and address root causes, leading to faster recovery times.

16. 🟡 `[LTIM]` What are the golden signals (RED/USE)?

    Ans: The golden signals are key metrics used to monitor the health and performance of a system. They include:
    - **RED**: Rate (the number of requests), Errors (the number of failed requests), and Duration (the time taken to process requests).
    - **USE**: Utilization (the percentage of resources being used), Saturation (the degree to which resources are overloaded), and Errors (the number of failed operations). Monitoring these signals helps identify performance bottlenecks and maintain system reliability.

## Security & Cost 🔥
17. 🟢🔥 `[GEN]` What is least privilege? (your 10+ resources story)

    Ans: Least privilege is a security principle that restricts users and systems to only the permissions necessary to perform their tasks, minimizing the risk of unauthorized access or actions. In my experience, I implemented least privilege across 10+ AWS resources by creating IAM policies that granted only the required permissions for each role or user. This approach reduced potential attack surfaces and improved overall security posture.

18. 🟡🔥 `[WMT][PP]` Where do you store secrets? Secrets Manager vs Parameter Store.

    Ans: Secrets can be securely stored using AWS Secrets Manager or AWS Systems Manager Parameter Store. Secrets Manager is designed for managing sensitive information like database credentials, API keys, and other secrets, providing automatic rotation and fine-grained access control. Parameter Store is suitable for storing configuration data and less sensitive information, offering hierarchical storage and versioning. Both services integrate with IAM for access control and can be used in CI/CD pipelines to securely retrieve secrets.

19. 🟡 `[CTS]` Encryption at rest vs in transit.

    Ans: Encryption at rest refers to the process of encrypting data when it is stored on disk or in a database, protecting it from unauthorized access if the storage medium is compromised. Encryption in transit refers to encrypting data as it travels over networks, ensuring that it cannot be intercepted or tampered with during transmission. Both types of encryption are essential for maintaining data confidentiality and integrity.

20. 🟡🔥 `[ACN][CAPG]` What security scans run in your pipeline? (shift-left: SAST, SCA, container, IaC)

    Ans: In our CI/CD pipeline, we implement a shift-left security approach by integrating various security scans early in the development process. This includes:
    - **SAST (Static Application Security Testing)**: Analyzing source code for vulnerabilities before deployment.
    - **SCA (Software Composition Analysis)**: Identifying known vulnerabilities in third-party libraries and dependencies.
    - **Container Security Scans**: Scanning container images for vulnerabilities and misconfigurations.
    - **IaC (Infrastructure as Code) Security Scans**: Validating infrastructure templates (e.g., Terraform, CloudFormation) for security best practices and compliance. 
    These scans help catch security issues early, reducing the risk of vulnerabilities reaching production.

21. 🟡 `[INFY]` IAM role vs user. How do CI/CD pipelines auth to AWS securely?

    Ans: An IAM user is an entity that represents a person or service with long-term credentials (username and password or access keys), while an IAM role is an entity that can be assumed by trusted entities (users, applications, or services) and provides temporary security credentials. In CI/CD pipelines, we use IAM roles to securely authenticate to AWS by assuming the role with temporary credentials, often through AWS STS (Security Token Service). This approach avoids hardcoding long-term credentials in the pipeline, enhancing security.

22. 🟡🔥 `[WMT]` How did you reduce AWS cost? (−35% story: right-size, autoscale, spot/reserved, lifecycle)

    Ans: To reduce AWS costs by 35%, I implemented several strategies:
    - **Right-sizing**: Analyzed resource utilization and adjusted instance types and sizes to better match workload requirements.
    - **Autoscaling**: Configured autoscaling groups to automatically adjust the number of instances based on demand, ensuring we only pay for what we need.
    - **Spot and Reserved Instances**: Leveraged spot instances for non-critical workloads and reserved instances for predictable workloads to take advantage of cost savings.
    - **Lifecycle Policies**: Implemented lifecycle policies for S3 buckets to automatically transition or delete unused data, reducing storage costs. 
    These combined efforts led to significant cost reductions while maintaining performance and reliability.

23. 🟢 `[TCS]` Shared Responsibility Model.

    
    Ans: The Shared Responsibility Model is a framework that defines the division of security responsibilities between cloud service providers (CSPs) and their customers. In this model, the CSP is responsible for the security "of" the cloud, which includes the infrastructure, hardware, and software that runs the cloud services. Customers are responsible for the security "in" the cloud, which includes managing their data, applications, access controls, and configurations. Understanding this model helps organizations implement appropriate security measures and maintain compliance in cloud environments.

24. 🟡 `[CMCST]` What is a WAF? GuardDuty / Config / Security Hub.

    Ans: A WAF (Web Application Firewall) is a security service that protects web applications by filtering and monitoring HTTP traffic between a web application and the internet. It helps prevent attacks such as SQL injection, cross-site scripting (XSS), and other common web exploits. AWS GuardDuty is a threat detection service that continuously monitors for malicious activity and unauthorized behavior. AWS Config provides a detailed view of the configuration of AWS resources and helps assess compliance with best practices. AWS Security Hub aggregates security findings from multiple AWS services and third-party tools, providing a centralized view of security posture.
